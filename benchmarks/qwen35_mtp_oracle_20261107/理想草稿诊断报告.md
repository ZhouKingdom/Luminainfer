# MTP-1 免费正确草稿诊断

这是测当前验证执行路径收益空间的乐观诊断，免费草稿由普通Graph完整输出预先提供，不能部署，也不能作为真实MTP性能成果。目标验证、Graph输入更新、S/conv历史写入、状态提交、页管理及调度仍实际执行。

上表合并两轮，耗时为rank0包装器同步边界的wall time，包含对应函数内通信/有限值检查，不是纯GPU kernel profile，也不包含函数外全部IPC/事务开销。批量路径改变草稿GEMM形状，草稿可能变化；最终目标输出仍严格一致。

免费草稿的参考前缀每次严格检查，所有提出token必须被接受；草稿模型前向和草稿IPC为零。仍保留Python查表/前缀检查开销，因此是当前路径下的乐观工程诊断，不是任意实现的数学性能上界。

正式共160次生成、7680个输出token；所有完整输出与各自普通Graph参考逐token一致，所有组资源回收、全部工作进程正常退出。原始计数、逐轮耗时、输出及源码快照见各目录result.json和source/。

若免费草稿仍不超过普通Graph，说明在该配置下仅消除真实草稿成本尚无已证明的收益空间，应优先改进验证执行路径；它不能否定其他数值后端、多步窗口或其他负载。若出现小幅收益，仍需给真实草稿预留预算并复测，不能直接声称MTP已提速。

本轮新增可选mtp_batch_draft=True：合并草稿投影、embedding/LM head和预测通信；attention仍按请求访问私有KV，草稿暂未捕获Graph。目标验证算术未改变。默认保持关闭。另修复事务分类依赖被包装函数名导致的多余S/conv快照，正式所有模式均基于修正后的同一源码。可选batched数值后端已有输出分歧，因此本诊断拒绝将固定普通输出作为该后端的完美草稿。

旧插桩额外快照与一次无效故障注入的说明见 [测量修正说明](测量修正说明.md)。相关CUDA回归118项通过；多卡故障验证结果见synthetic_batch_fixed_tp2.json及synthetic_batch_tp4/8.json，须同时检查passed与processes_exited。
